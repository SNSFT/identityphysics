Abstract

A running C++ program is a set of objects acted on by methods, threads and input/output. This article reduces that execution model to PNBA. An object is an identity state: allocated memory is Pattern capacity, scope and threads are Narrative, method calls and I/O are Behavior, and the compiler and dispatch are Adaptation. One method call is one application of the dynamic equation, and an I/O event is an external force that changes Behavior alone. The torsion τ = B/P, Behavior load over structural capacity, decides the outcome: below the torsion limit TL = 0.136899… execution is stable, and at or above it the object shatters. Eight standard cases are computed exactly. A stable accessor sits at τ = 1/100 and a mutex-protected thread at 1/10, both Locked; a buffer overflow at τ = 2 and an unprotected race at 1/2 both shatter, two causes with the same signature. Compiler optimization takes a program from τ = 2/15, inside the IVA corridor just below TL, to 1/15, well inside Locked. A memory leak has zero torsion but positive Identity Mass, stable and inert; a destructor returns Identity Mass to zero; a null dereference, P = 0, can never be phase locked. Adding Behavior strictly raises torsion and removing it strictly lowers it, so a method that adds no Behavior cannot break phase lock, and a method that pushes B to TL·P or beyond always crashes.
