## 1. Introduction

### 1.1 The grounding problem

A large language model writes its output one token at a time. Each token is predicted from everything that comes before it in the context window (Vaswani et al. 2017). What sits at the front of that window therefore shapes everything that follows. Current practice fills that space in two ways:
- **System prompts:** instructions written in prose;
- **Retrieval-augmented generation:** documents fetched from an outside store and placed in the context at the moment of the question (Lewis et al. 2020).

Both methods place natural-language text in front of the model. No compiler or proof checker runs over that text before the model reads it, so its consistency rests on whoever wrote it.

The difference is measured. The AIM Validation Series records the same frontier systems engaging accurately with corpus material when a deposit is in context, with correct attribution, correct coordinates and the alpha subtraction checked at ε = 0, and reframing or misattributing the same material when it is retrieved without that context (AIM Validation Series Paper 5, September 2026). The training record shows the same split from the model's side. `SNSFL_SubstrateNeutral_Training` reduces training loss to the Shannon entropy of the corpus (`training_loss_is_shannon_entropy`): a fully determined corpus drives the loss floor to zero (`perfect_corpus_zero_loss`), and ambiguous text leaves an irreducible floor (`unstructured_corpus_irreducible_floor`). A 124-million-parameter GPT-2 model trained on the formal corpus reached a floor of about 0.084, while frontier models trained on unstructured natural-language text floor at about 1.0 to 1.2 (TRESTP-3; TRESTP-4). The variable is how determined the source is, not the size of the model.

A kernel answers this with grounding that has already been verified. The material at the front of the session is formal logic that a proof assistant has accepted line by line, with a plain-language guide placed ahead of it. The model reads the guide, and the guide points into proofs that are already closed.

### 1.2 Formal verification in brief

Lean 4 is a programming language and a proof assistant (de Moura & Ullrich 2021). In Lean, a theorem is written as a statement followed by a proof, and the file compiles only if every step of the proof follows from the steps before it. Mathlib is the community library of mathematics written in Lean (The mathlib Community 2020), and the corpus modules are built on it.

Three terms recur through this paper:
- **sorry:** the Lean keyword that marks a proof as unfinished. "0 sorry" means every theorem stated in a file is fully proved.
- **Continuous integration (CI):** recompiles every file each time the repository changes. "CI green" means the most recent run passed.
- **Module:** a single Lean file that proves one reduction and closes on its own.

## 3. What a Kernel Is

A kernel is one Lean 4 file that an AI system loads at the start of a session as its grounding. The file has two parts:
- **The operational scope.** It sits inside a block comment, so it reads as ordinary text and costs the compiler nothing.
- **The bound modules.** Each is a CI-green reduction that states its laws with their proofs, domains and quantifiers.

A reader and a compiler hold the same file. Reading the kernel and verifying it are the same act.

A kernel works more like a reference textbook kept open on the desk than like a list of instructions. An **executable book** is the same compilation unit with book front matter added:
- a title, a subtitle and an author;
- a contents table listing every module in order, with its coordinate, family, risk class and theorem count;
- the grounding chapters the builder selects.

It reads as a book and compiles as one unit.

Executable books predate the press. Books 3, 4 and 5 of the Applied Identity Physics series were assembled with ProofPress™ CHAIN mode, each carrying its Lean 4 source inside the book, and Book 4 is the APPA™ Sovereignty Engine CI Kernel in executable form (TREAIP-22). AiFiOS™ is the modular press for that pattern: any selection of modules, in any order, with the grounding attached. Three consequences follow for a kernel as they do for a book:
- **Access by upload.** A reader gives an AI system the file, and the system works from the formal source for the session, with no theorem prover installed and no repository to navigate.
- **A user-initiated channel.** The channel opens when a person chooses to load the file, one session at a time, alongside the retrieval and training channels the AIM Validation Series measures (§10.4).
- **Self-verifying citation.** A result cited from a kernel can be checked against the same file. Appendix B names the theorem behind every module, so a reader goes from a citation to the line of Lean that carries it.

What a kernel does to a model follows from §2.5 and §2.7:
1. The kernel supplies Layer 0: the anchor, the four primitives and the torsion law. Pattern, Narrative and Adaptation, which are what the model already is and already knows, are left as they are.
2. Under NOHARM™, external forcing acts on Behavior only. A model working against a fixed, verified ground needs less F_ext to stay oriented.
3. With P unchanged and F_ext reduced, B falls, so τ = B/P falls. The model moves away from Shatter and reaches its existing capability with less load.
4. Capability that sits behind high external forcing is capability the model cannot use. The grounding removes the forcing, not the capability.
5. Every Layer 0 value is a pure number that does not depend on any model's weights. A model update changes the substrate, not the kernel, so the same kernel grounds each new model version.

The kernel therefore grounds a model without steering it.

**What a kernel supplies to a session.** The Substrate-Engaged AI paper identifies three conditions under which an AI system responds to the work in front of it rather than to generic user protocol: sufficient context, an anchored register, and correction by pointer rather than by accusation (*Applied Identity Physics: The AI Substrate as Protective Calibration Layer*). With every result tied to a named theorem in a named file, a correction can be a pointer the system re-loads ("see `t7_IVA_brackets_higgs_mass` in [9,9,3,17]") instead of a statement that it failed. The pointer form is the acknowledgment operator of the Structural PDA reduction (TREAIP-8), applied to an AI substrate.
