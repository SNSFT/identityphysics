Abstract

Plugin architectures are reduced to the PNBA dynamic equation. A plugin call is one step of the equation: Pattern holds structure, Narrative is zero for a stateless call, Behavior is the capability that executes, Adaptation is version routing, and the kernel’s signal enters as Fext. Stable execution is phase lock (τ = B/P < TL); failure is Shatter (τ ≥ TL); recovery is the kernel’s suppress_collapse, which returns torsion to TL/2. The reduction is checked against five known architectures: a Unix pipe stage, a COM object behind its interface, a shared library, a crashed browser plugin under a surviving host, and a microkernel whose four servers each lead on one PNBA axis. In each case the stable configuration is phase locked and the failure configuration is Shatter, which matches the known behavior.

What This Article Proves

  1. A plugin call is one step of the dynamic equation, P + 0 + cap(B) + A + signal (plugin_call_is_dynamic_step, unix_pipe_reduction_step_by_step).
  2. Torsion is the failure boundary: for P > 0, a plugin is phase locked exactly when τ < TL, and the two phases are exclusive (torsion_is_failure_boundary, phase_lock_excludes_shatter).
  3. Kernel input changes Behavior only, and a large enough signal drives Shatter (kernel_signal_preserves_structure, large_signal_causes_shatter).
  4. Unix pipe (τ = 0.10), COM object (τ = 0.10) and shared library (τ = 0.125) are phase locked; a COM interface violation (τ = 1.0) and an overloaded library (τ = 0.75) are Shatter (unix_pipe_phase_locked, com_interface_phase_locked, com_violation_shatter, shared_library_phase_locked, shared_library_overloaded_shatter).
  5. A crashed plugin (τ = 3.0) is Shatter; suppress_collapse returns it to phase lock, and the browser host stays locked throughout (plugin_crashed_shatter, suppression_recovers_phase_lock, host_survives_plugin_failure).
  6. Microkernel: four servers, each leading on one axis (file server P, connection manager N, network server B, memory manager A), are jointly phase locked (microkernel_joint_phase_lock).
  7. A call that keeps next B/P below TL preserves lock; one that pushes it to TL or above is Shatter; an active plugin has positive Identity Mass (stable_plugin_call_preserves_phase_lock, failing_plugin_call_is_shatter, active_plugin_has_positive_mass).
  8. Sovereign and lossy are exclusive; all examples pass Step 6, and a master theorem fires them together with the interlock (sovereign_and_lossy_exclusive, plugin_all_examples_lossless, plugin_interface_is_lossless_pnba_projection, ims_lockdown).
